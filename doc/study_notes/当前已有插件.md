**和 C++ 开发最相关的插件**

1. `llvm-vs-code-extensions.vscode-clangd`

这是你当前 C++ 体验里最关键的插件之一。它背后运行的是 `clangd`，负责：

- 头文件查找诊断；
- 代码补全；
- 跳转定义；
- 查找引用；
- 语义高亮；
- 编译错误/警告诊断；
- 基于真实编译参数理解宏、include path、C++ 标准。

但 clangd 有一个前提：它最好读取 `compile_commands.json`。

如果没有这个文件，或者 clangd 没指向正确 build 目录，它就只能猜：

```text
这个 cpp 文件用什么 include path？
用 C++17 还是 C++20？
有哪些宏定义？
```

于是就容易出现：

```text
'su/evaluator.hpp' file not found
```

对于 SPICEUnion，clangd 应该读取：

```text
build/default/compile_commands.json
```

或者 external 构建时读取：

```text
build/external/compile_commands.json
```

如果当前项目还没有生成这个文件，clangd 报找不到头文件就很正常。

2. `ms-vscode.cpptools`

这是 Microsoft 官方 C/C++ 插件，负责：

- IntelliSense；
- 调试集成；
- 代码浏览；
- include error squiggles；
- C/C++ 配置识别。

它和 clangd 有一定功能重叠。两者都可能报 C++ 诊断。

也就是说你现在机器上同时装了：

```text
clangd
cpptools
```

这不是错，但要小心：如果两个都在同时做诊断，可能出现重复报错，甚至一个说没问题、一个说找不到头。

一般有两种推荐路线。

路线 A：以 clangd 为主

```text
clangd 负责 C++ 补全/诊断/跳转
cpptools 主要保留调试能力
```

这时应该配置 clangd 读取 `compile_commands.json`。

路线 B：以 cpptools 为主

```text
cpptools 负责 C++ IntelliSense
CMake Tools 提供配置源
```

这时应该配置：

```json
{
  "C_Cpp.default.configurationProvider": "ms-vscode.cmake-tools"
}
```

我的建议：**这个项目更适合 clangd 为主，CMake Tools 提供构建，cpptools 保留调试。**

原因是 SPICEUnion 是 CMake/C++ 项目，clangd 对 `compile_commands.json` 的支持很直接，诊断也更贴近真实 Clang 工具链。

3. `ms-vscode.cmake-tools`

这是 CMake 项目最重要的 VSCode 插件。它负责：

- 识别 `CMakeLists.txt`；
- 选择 configure preset；
- 选择 build preset；
- 执行 configure；
- 执行 build；
- 执行 CTest；
- 给 C/C++ 插件提供编译配置；
- 管理 build 目录。

它不是语言服务器，但它是编辑器理解 CMake 项目的入口。

你应该通过它来操作：

```text
CMake: Select Configure Preset
CMake: Configure
CMake: Build
CMake: Run Tests
```

如果没有 CMake Tools，VSCode 就更容易不知道项目的 include path。

4. `twxs.cmake`

这个插件主要负责 CMake 文件本身的语言支持，比如：

- `CMakeLists.txt` 语法高亮；
- `.cmake` 文件高亮；
- CMake 命令识别。

它和 `ms-vscode.cmake-tools` 不同。

简单理解：

```text

  -> 帮你更舒服地编辑 CMake 文件

ms-vscode.cmake-tools
  -> 真正帮你 configure/build/test CMake 项目
```

所以 `twxs.cmake` 有用，但它不能解决 `su/evaluator.hpp` 找不到的问题。

5. `ms-vscode.cpptools-extension-pack`

这是 C/C++ 扩展包，本身不是主要功能插件。它通常用来一次性安装或推荐：

- CMake Tools；
- CMake 语言支持；

它更像“安装合集”，不是负责 include path 诊断的核心。

6. `ms-vscode.cpp-devtools`

这是微软的 C/C++ 辅助开发工具插件，偏增强体验。具体作用通常围绕 C++ 项目开发辅助功能，不是当前 include path 问题的核心来源。

当前你要重点关注的不是它，而是：

```text
clangd
cpptools
cmake-tools
compile_commands.json
```

**和当前问题直接相关的判断**

你当前这套插件有点像这样：

```text
CMake Tools 已安装
clangd 已安装
cpptools 已安装
但是项目没有 compile_commands.json
也没有 .vscode/settings.json 指明配置来源
```

所以 VSCode 报：

```text
'su/evaluator.hpp' file not found
```

并不奇怪。

这不是插件少了，而是插件之间还没被项目配置串起来。

正确链路应该是：

```text
CMakePresets.json
  -> cmake --preset default
  -> build/default/compile_commands.json
  -> clangd 读取 compile_commands
  -> VSCode 正确认识 include/su/evaluator.hpp
```

或者如果走 cpptools 路线：

```text
CMake Tools
  -> 提供 configure/build target 信息
  -> cpptools 作为 configurationProvider 读取 CMake Tools
  -> VSCode 正确认识 include/su/evaluator.hpp
```

**我对你当前 VSCode 插件状态的判断**

你当前插件并不缺，甚至 C++ 插件已经比较齐了：

```text
clangd 有
cpptools 有
CMake Tools 有
CMake 语法插件有
```

问题是项目配置还没有把它们串起来：

```text
缺 CMakePresets.json
缺 compile_commands.json
缺 .vscode/settings.json
```

所以结论不是“再装插件”，而是“补标准项目配置”。

**我建议你选择的 C++ 配置路线**

我建议 SPICEUnion 采用这条：

```text
CMake Tools 管 configure/build/test
clangd 管 C++ 补全/跳转/诊断
cpptools 保留调试能力
```

项目里补：

```text
CMakePresets.json
.vscode/settings.json
.clang-format
```

其中 `.vscode/settings.json` 可以先写成：

```json
{
  "C_Cpp.intelliSenseEngine": "disabled",
  "clangd.arguments": [
    "--compile-commands-dir=${workspaceFolder}/build/default"
  ],
  "cmake.useCMakePresets": "always"
}
```

这表示：

```text
C++ 语义分析交给 clangd
CMake 项目管理交给 CMake Tools
不要让 cpptools 和 clangd 同时抢 IntelliSense 诊断
```

如果你更习惯 Microsoft C/C++ 插件，也可以走另一条：

```json
{
  "C_Cpp.default.configurationProvider": "ms-vscode.cmake-tools",
  "cmake.useCMakePresets": "always"
}
```

但二者我不建议同时作为主要诊断源。

我的偏好是第一种：**clangd 主导 C++ 语义，CMake Tools 主导构建**。这套更清晰，也更贴近现代 C++ 项目。
