# SPICEUnion 开发路线图

时间：2026-08-03

## 使用方式

本文档是 SPICEUnion 的施工路线图，负责把 `CPP版本开发计划书.md` 中的
M0 / M1 / M2 / M3 拆成可执行、可验证、可提交的小阶段。

文档分工如下：

- 根 `README.md`：项目入口、当前状态、范围边界。
- 根 `TODO`：当前未完成任务、暂缓池、监控项。
- `doc/CPP版本开发计划书.md`：项目总纲、架构、里程碑、验收标准。
- `doc/开发路线图.md`：阶段任务、文件产出、测试产出、完成定义。

执行原则：

- 每个阶段只解决一个明确层级的问题。
- 每个阶段必须有可运行的验证命令或可检查的文档产出。
- 已完成事项及时从根 `TODO` 收口删除。
- 行为、结构、入口、配置、流程变化时，同步更新 README / TODO / 相关文档。
- 性能数字实测前只能写成目标，不得写成已完成结果。

## 阶段总览

```text
M0   项目启动与可构建骨架
M1.0 执行层核心类型与 FakeSession 契约
M1.1 SpectreSession 生命周期闭环
M1.2 参数写入、单任务运行与失败恢复
M1.3 并发 Evaluator 与 Python 等价门面
M2   最小结果 IR、PSF helper 与一致性测试
M3   多仿真器抽象收敛
M3.5 OrderedConcurrentPool 提取
M4   部署、基准与 demo
M5   面试材料打磨
```

V1 的实际开工顺序只关注 M0 到 M2。M3 之后保留方向，不提前把抽象做死。

## M0：项目启动与可构建骨架

### 目标

让 SPICEUnion 从文档仓库变成可配置、可编译、可测试的 C++ 项目。

M0 不接真实 Spectre，不写 PSF parser，不写 Python binding。M0 的价值是把项目骨架、
目录职责、构建入口和最小测试路径钉住。

### 前置条件

- 已阅读并遵守根 `AGENTS.md`。
- 已理解 `spectre_materials/src/spectre_interactive/` 的行为基线。
- 根 `README.md`、根 `TODO`、`doc/CPP版本开发计划书.md` 已能说明项目方向。
- 确认是否初始化 Git 仓库；若初始化，先提交当前文档基线。

### 任务清单

- 初始化 Git 仓库或确认外部版本管理方式。
- 新增根 `CMakeLists.txt`。
- 新增 `include/`、`include/su/`、`src/`、`tests/`、`bindings/`、`bench/`、`scripts/`。
- 为主要目录新增 `README.md`，写明目录职责与命名规则。
- 建立一个最小库 target，例如 `spiceunion_core`。
- 建立一个最小测试 target，例如 `spiceunion_smoke_test`。
- 让 configure / build / test 三步能本地跑通。

### 文件产出

- `CMakeLists.txt`
- `include/README.md`
- `include/su/README.md`
- `src/README.md`
- `tests/README.md`
- `bindings/README.md`
- `bench/README.md`
- `scripts/README.md`
- `tests/smoke_test.cpp`

### 测试产出

最小 smoke test 只验证测试框架和库 target 可链接，不承载业务逻辑。

验收命令：

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

### 完成定义

- 仓库版本管理状态明确。
- CMake configure / build / test 三步通过。
- 主要目录都有 README。
- 根 `TODO` 中 M0 已完成项已收口，只保留下一阶段任务。

### 不做事项

- 不接真实 `spectre`。
- 不实现 `SpectreSession`。
- 不写 C ABI。
- 不写 pybind11。
- 不写 PSF parser。
- 不设计完整网表 IR。

## M1.0：执行层核心类型与 FakeSession 契约

### 目标

在不依赖真实仿真器的情况下，先把执行层数据结构和调度契约写成代码。

这一阶段的重点是继承 Python 版 `GenericEvaluator.run(states, parse_func)` 的行为语义，
但 C++ 核心不承载 Python 任意返回对象。C++ 核心先只返回有序的 `TaskResult`。

### 任务清单

- 定义 `EvaluatorOptions`。
- 定义 `ParameterState`。
- 定义 `TaskStatus`。
- 定义 `TaskResult`。
- 定义 `BatchResult` 或等价结果集合。
- 定义 `SimulatorSession` 接口。
- 实现 `FakeSession`，可配置启动成功/失败、运行成功/失败、延迟、完成顺序。
- 实现最小 `SimulatorPool`，负责 session 生命周期与空闲 worker 队列。
- 实现最小 evaluator facade：`states -> ordered TaskResult`。

### 建议文件产出

- `include/su/core.hpp`
- `include/su/session.hpp`
- `include/su/evaluator.hpp`
- `src/core/`
- `src/session/`
- `src/pool/`
- `tests/fake_session_test.cpp`
- `tests/evaluator_contract_test.cpp`

### 测试清单

- 空输入返回空结果。
- 单 worker 单任务成功。
- 多任务完成顺序乱序，但结果按输入顺序返回。
- 单任务失败只影响对应结果。
- worker 启动失败向上传播。
- 启动失败后已启动 worker 被 stop。
- 每个 evaluator 使用独立 namespace。
- worker 工作目录不碰撞。
- cleanup 可重复调用。

### 完成定义

- 所有 M1.0 契约测试通过。
- 核心类型命名稳定，不使用 `new`、`tmp`、`v2` 等阶段词。
- 根 README 或计划书中若接口边界发生变化，已同步更新。

### 不做事项

- 不启动真实子进程。
- 不解析 Spectre stdout。
- 不做 C ABI 内存所有权设计之外的绑定实现。
- 不处理 PSF 文件。

## M1.1：SpectreSession 生命周期闭环

### 目标

实现真实 Spectre interactive session 的最小生命周期闭环：启动、握手、停止、错误保留。

这一阶段只验证“能不能稳定拉起和关闭 Spectre”，不做参数写入和仿真运行。

### 前置条件

- M1.0 的 FakeSession 契约测试稳定通过。
- 当前机器存在 `spectre` 可执行文件。
- 做真实仿真前确认 PDK 依赖，例如 `/dev/shm/pdk_cache/toplevel.scs`。

### 任务清单

- 实现 `SpectreSession` 类。
- 准备 worker 工作目录。
- 启动命令：

```text
spectre <netlist_path> +interactive -64 -o <work_dir>
```

- 读取 stdout，等待握手标志：

```text
Entering Skill interactive front end
```

- 握手成功后写入：

```text
(setq top (sclGetCircuit ""))
```

- 实现 graceful stop：

```text
(sclQuit)
```

- 实现必要时强杀。
- 保留启动失败、握手失败、EOF、timeout 的最近 stdout 片段。

### 建议文件产出

- `include/su/spectre_session.hpp`
- `src/session/spectre_session.cpp`
- `tests/spectre_session_lifecycle_test.cpp`
- 可选：`scripts/check_spectre_env.sh`

### 测试清单

- 无 `spectre` 环境时测试可跳过或明确报出 external dependency。
- 无效 netlist 时返回握手失败并包含错误信息。
- 成功握手后可 stop。
- stop 可重复调用。
- 握手 timeout 后进程被回收。

### 完成定义

- FakeSession 测试仍全部通过。
- Spectre 生命周期测试在具备外部依赖时通过。
- 没有真实 Spectre 时，默认 CI 不被阻塞。

### 不做事项

- 不写参数。
- 不运行 `(sclRun "all")`。
- 不解析 `.raw` 结果。
- 不引入 Python binding。

## M1.2：参数写入、单任务运行与失败恢复

### 目标

在单个真实 Spectre session 上完成一次参数写入、运行、完成等待和失败恢复。

### 任务清单

- 为 `ParameterState` 生成 SKILL 参数写入命令。
- 写入形式：

```text
(sclSetAttribute (sclGetParameter top "key") "value" <value>)
```

- 运行命令：

```text
(sclRun "all")
```

- 等待完成标志：

```text
Peak resident memory used
t
```

- 识别 `nil` 为失败。
- 识别 EOF / BrokenPipe / OSError / timeout，并回收进程。
- 实现有限次 restart attempt。
- 单任务失败返回失败 `TaskResult`，不抛散到整个 batch，除非属于启动阶段 fatal failure。

### 建议文件产出

- `src/session/spectre_protocol.cpp`
- `include/su/spectre_protocol.hpp`
- `tests/spectre_protocol_test.cpp`
- `tests/spectre_single_run_test.cpp`

### 测试清单

- SKILL 命令生成格式正确。
- 参数值使用稳定的科学计数法格式。
- `t` 完成路径返回成功。
- `nil` 路径返回失败。
- timeout 后进程被回收。
- transport failure 后按策略重启。

### 完成定义

- 单 worker 连续多次运行稳定。
- 失败路径有测试覆盖。
- 真实 Spectre 测试与无 Spectre 的协议单测分离。

### 不做事项

- 不实现多 worker batch。
- 不做 PSF parser。
- 不写性能基准结论。

## M1.3：并发 Evaluator 与 Python 等价门面

### 目标

把 M1.0 的调度契约和 M1.2 的真实 session 能力合起来，形成 C++ 版批量执行核心。

### 任务清单

- 实现 evaluator 级 namespace 自动生成。
- 实现 worker 目录布局：

```text
<work_dir_base>/<workspace_namespace>/worker_<id>
```

- 并行预热所有 worker。
- 用空闲 worker 队列动态调度任务。
- 结果按提交 index 回填。
- 单任务失败隔离。
- 实现 reload workers。
- 初步设计 C ABI handle 与 `TaskResult` 输出结构。
- Python binding 暂时可只做薄门面草案，不要求完整发布。

### 建议文件产出

- `include/su/evaluator.h`
- `include/su/evaluator.hpp`
- `src/core/evaluator.cpp`
- `src/pool/simulator_pool.cpp`
- `tests/evaluator_parallel_test.cpp`
- `tests/evaluator_failure_test.cpp`

### 测试清单

- `num_workers=1` 顺序执行。
- `num_workers>1` 动态调度。
- 任务完成乱序、结果保序。
- 两个 evaluator 并发时 namespace 不碰撞。
- worker 启动失败时 shutdown 已启动 worker。
- 单任务失败不影响其他任务。
- 空输入返回空结果。

### 完成定义

- C++ 执行层覆盖 Python 版主契约。
- FakeSession 与真实 Spectre 路径都能通过对应测试。
- C ABI 的所有权规则写入文档。

### 不做事项

- 不要求完整 Python wheel。
- 不要求 MATLAB MEX。
- 不要求 PSF parser 完整落地。

## M2：最小结果 IR、PSF helper 与一致性测试

### 目标

实现服务当前 Python `task_library.py` 行为的最小结果 IR 和 PSF helper。

M2 不追求完整 EDA 结果模型，只覆盖 V1 必须使用的 dc/ac/tran/sens helper。

### 最小 IR 范围

- `.raw` 结果目录定位。
- `OperatingPoint` / scalar value。
- `AcResponse`：frequency、magnitude_db、phase_deg。
- `TranWaveform`：time、value。
- `SensitivityEntry`：node、parameter、sensitivity、parameter_value。

### 任务清单

- 实现 `.raw` 目录定位。
- 实现 `dcOp.dc` 单信号读取。
- 实现 `ac.ac` 频率、幅度、相位读取。
- 实现 UGBW / phase margin 计算。
- 实现 `tran.tran` 建立时间计算。
- 实现 legacy sensitivity 结果读取。
- 用 Python `libpsf` 结果做数值一致性对照。
- 建立 Google Benchmark 基准入口。

### 建议文件产出

- `include/su/result_ir.hpp`
- `include/su/psf_reader.hpp`
- `include/su/result_helpers.hpp`
- `src/parse/`
- `tests/result_ir_test.cpp`
- `tests/psf_reader_test.cpp`
- `tests/result_helper_test.cpp`
- `bench/psf_reader_bench.cpp`

### 测试清单

- 找不到 `.raw` 时回退到 work_dir。
- 缺失结果文件时返回空结果或失败状态。
- dc 单值与 Python helper 对齐。
- ac 曲线与 Python helper 对齐。
- UGBW / PM 计算与 Python helper 对齐。
- tran settling 与 Python helper 对齐。
- sensitivity 条目 key 与字段结构对齐。

### 完成定义

- 覆盖当前 Python `task_library.py` helper 行为。
- 一致性测试有固定 fixture。
- 性能 benchmark 能跑，但实测数字未稳定前只作为目标记录。

### 不做事项

- 不做完整网表 IR。
- 不做 noise / stb / pz / xf 等额外 analysis。
- 不承诺所有 PSF 方言。
- 不把业务指标写入 parser 层。

## M3：多仿真器抽象收敛

### 目标

在 Spectre V1 跑通之后，引入第二个真实仿真器实现，用真实需求收敛抽象。

优先级：

```text
Ngspice > Xyce > Hspice
```

### 任务清单

- 选择一个公开可运行的 Ngspice 示例。
- 实现 Ngspice session 或 batch adapter。
- 将 Ngspice 输出转换到 M2 的最小结果 IR。
- 比较 Spectre / Ngspice 在同类任务上的 IR 复用情况。
- 只在两个真实实现共同需要时扩展 IR。

### 完成定义

- 至少两个仿真器能输出同类 IR。
- IR 扩展有真实消费者。
- 文档记录哪些抽象被保留、哪些被拒绝。

### 不做事项

- 不为了未来仿真器提前设计全量网表 IR。
- 不声称完整支持 Hspice / Xyce，除非真实落地。

## M3.5：OrderedConcurrentPool 提取

### 目标

在 SPICEUnion 内部池语义稳定后，把域无关部分提取为独立库。

### 提取条件

- SPICEUnion 已经真实使用池组件。
- API 经历过至少一次 Spectre 路径验证。
- 保序、生命周期、故障恢复语义稳定。
- 有独立测试与 benchmark 价值。

### 任务清单

- 新建或迁移到 `OrderedConcurrentPool` 仓库。
- 提取域无关 worker 生命周期接口。
- 提取保序调度与结果回收。
- 提取故障/超时重建策略。
- SPICEUnion 改为依赖该库。

### 完成定义

- `OrderedConcurrentPool` 可独立构建、测试、benchmark。
- SPICEUnion 依赖外部池库后测试全部通过。
- README 清楚解释它不是普通线程池，而是带保序与故障恢复语义的 worker 池。

## M4：部署、基准与 demo

### 目标

把项目整理成可展示、可复现、可安装的形态。

### 任务清单

- 提供本地 install 脚本。
- 提供单二进制 demo 或最小 Python demo。
- 固定 benchmark 场景。
- 记录机器信息、数据规模、重复次数和统计方法。
- 生成 Python vs C++ 的调度和解析对比图。

### 完成定义

- demo 可在干净环境中按 README 跑通。
- benchmark 数字可复现。
- 性能结论与测量条件一起记录。

### 任务清单
