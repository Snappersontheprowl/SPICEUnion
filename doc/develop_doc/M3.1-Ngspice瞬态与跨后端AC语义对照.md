# M3.1 Ngspice 瞬态与跨后端 AC 语义对照

时间：2026-08-06

本文记录 M3.1 的事实状态：在 M3.0 Ngspice RC low-pass AC 最小接入基础上，继续加入
Ngspice RC charging transient，并开始把 AC / TRAN 的检查口径从“能跑通”推进到“符合
ResultIR 语义”。

## 当前结论

M3.1 已完成 Ngspice TRAN 最小接入。

当前 `NgspiceSession` 支持两个内置 batch 任务：

| 任务 | Netlist | 输出 | ResultIR |
|---|---|---|---|
| `NgspiceBuiltinTask::kRcAc` | `rc_ac.cir` | `rc_ac.out` 三列 `frequency real imag` | `AcResponse` |
| `NgspiceBuiltinTask::kRcTran` | `rc_tran.cir` | `rc_tran.out` 两列 `time value` | `TranWaveform` |

这一步没有引入完整 netlist IR，也没有把 Ngspice raw binary parser 放入项目。M3.1 的目标是
验证已有 `AcResponse` 与 `TranWaveform` 可以承载第二个真实仿真器的输出，而不是把 Ngspice
一次性产品化为完整 backend。

## 为什么增加 `NgspiceBuiltinTask`

`ParameterState` 当前定义为：

```cpp
using ParameterState = std::map<std::string, double>;
```

它只适合表达数值参数，例如电阻、电容、扫频范围、TRAN 步长等，不适合表达
`analysis = "tran"` 这类字符串任务类型。

因此 M3.1 增加：

```cpp
enum class NgspiceBuiltinTask {
  kRcAc,
  kRcTran,
};
```

任务类型由 `NgspiceSession` 或 evaluator factory 捕获，`ParameterState` 继续只表达数值
覆盖。这避免了把 `"analysis_kind" = 1.0` 这类哑编码塞进参数层。

## 公共入口

公开头文件：

```text
include/su/ngspice_session.hpp
```

新增或扩展的主要接口：

```cpp
enum class NgspiceBuiltinTask {
  kRcAc,
  kRcTran,

struct NgspiceRcTranConfig {
  double resistance_ohm = 1000.0;

  double step_s = 1.0e-11;

NgspiceRcTranConfig ngspice_rc_tran_config_from_state(const ParameterState& state);

std::string render_ngspice_rc_tran_netlist(

    const std::string& data_path,
    const std::string& signal_name);
```

`NgspiceSession` 构造函数增加 task 参数，默认仍为 RC AC：

```cpp
NgspiceSession(std::size_t worker_id,
               EvaluatorOptions options,
               std::string work_dir,
               NgspiceBuiltinTask task = NgspiceBuiltinTask::kRcAc);
```

`evaluator.hpp` 增加带 task 的 Ngspice factory 重载：

```cpp
SessionFactory make_ngspice_session_factory(NgspiceBuiltinTask task);
Evaluator make_ngspice_evaluator(EvaluatorOptions options, NgspiceBuiltinTask task);
```

旧入口仍保留，默认运行 RC AC：

```cpp
SessionFactory make_ngspice_session_factory();
Evaluator make_ngspice_evaluator(EvaluatorOptions options);
```

## RC charging TRAN 参数

`ngspice_rc_tran_config_from_state()` 支持：

| 参数名 | 默认值 | 含义 |
|---|---:|---|
| `resistance_ohm` | `1000.0` | RC 电阻 |
| `capacitance_f` | `1.0e-12` | RC 电容 |
| `input_voltage_v` | `1.0` | 输入 DC 电压 |
| `tran_step_s` | `1.0e-11` | TRAN 输出步长 |
| `tran_stop_s` | `1.0e-8` | TRAN 终止时间 |

默认配置对应：

```text
R = 1 kΩ
C = 1 pF
τ = RC = 1 ns
stop = 10 ns = 10τ
```

## 当前 TRAN netlist

M3.1 的内置 TRAN netlist 形态：

```spice
* SPICEUnion Ngspice RC charging transient fixture
Vin in 0 dc <input_voltage_v>
R1 in out <resistance_ohm>
C1 out 0 <capacitance_f> ic=0
.control
set filetype=ascii
tran <tran_step_s> <tran_stop_s> uic
wrdata rc_tran.out v(out)
quit
.endc
.end
```

这里使用 `ic=0` 与 `uic`，目的是让电容初始电压明确为 0，并得到标准 RC charging 曲线：

```text
v(out, t) = Vin * (1 - exp(-t / (R*C)))
```

## Ngspice TRAN 输出格式

本机 Ngspice revision 27 下，`wrdata rc_tran.out v(out)` 输出两列：

```text
time value
```

示例：

```text
0.00000000e+00  0.00000000e+00
1.00000000e-13  9.99900010e-05
2.00000000e-13  1.99970004e-04
```

当前 parser：

```cpp
ReadResult<TranWaveform> read_ngspice_wrdata_tran_waveform(data_path, signal_name);
```

映射关系：

```text
column 1 -> TranWaveform.time_s
column 2 -> TranWaveform.value
```

parser 保持严格风格：

- 空路径或空 signal 返回 `kInvalidInput`；
- 文件不存在返回 `kFileNotFound`；
- 非空行必须正好两列；
- 少列、多列或非数字返回 `kParseError`；
- 空文件返回 `kParseError`。

## AC / TRAN 语义检查

M3.1 的测试不只检查“能执行”，还检查基本物理语义。

RC low-pass AC external 测试会确认：

- `AcResponse` shape 一致；
- 频率单调递增；
- 低频增益接近 0 dB；
- -3 dB 频率接近理论值：

```text
fc = 1 / (2πRC)
```

RC charging TRAN external 测试会确认：

- `TranWaveform` shape 一致；
- 时间单调递增；
- 波形从 0 开始，向输入电压单调充电；
- `t = τ` 附近接近 `Vin * (1 - exp(-1))`；
- `t = 5τ` 附近接近 `Vin * (1 - exp(-5))`；
- 终点接近 `Vin`。

这些检查说明 M2 的 `AcResponse` / `AcDerivedView` / `TranWaveform` 不是 Spectre-only
结构，而是可以承载 Ngspice 的真实输出。

## 当前边界

M3.1 仍不做：

- 完整 Ngspice netlist 模板系统；
- 完整 netlist IR；
- Ngspice binary raw parser；
- `.op` / `.dc` / `.noise` / `.stb` 的通用读取；
- MOS / PDK 模型接入；
- Xyce / Hspice 占位；
- C ABI / Python binding。

`.dc` 是否引入新的 ResultIR，必须等待真实消费者或至少第二个真实 backend 共同需要后再决定。

## 后续候选方向

后续 M3 推荐优先：

- 比较 Spectre / Ngspice 在同类 AC 或 TRAN 任务上的 IR 复用情况。
- 如果需要 `.dc` sweep，先用最小真实消费者定义输出形态，再决定是否扩展 ResultIR。
- 只有两个真实 backend 共同需要时，再扩展 `EvaluatorOptions` 或引入 netlist 模板接口。
