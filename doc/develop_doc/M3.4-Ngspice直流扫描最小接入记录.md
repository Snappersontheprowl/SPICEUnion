# M3.4 Ngspice 直流扫描最小接入记录

时间：2026-08-06

本文记录 M3.4 的事实状态：在 Ngspice AC / TRAN 已经接入并完成 Spectre / Ngspice
同类语义对照之后，补充 Ngspice `.dc` 简单 sweep 的最小可运行路径。

## 当前结论

M3.4 已完成 Ngspice `.dc` 简单 sweep 最小接入。

这一步实现的是：

```text
每个 evaluator task 运行一次 Ngspice batch-mode .dc sweep
```

不是：

```text
.op 单点 operating point
MOS I-V 全量曲线工具
完整 netlist IR
Ngspice binary raw parser
```

## 为什么选择电阻分压 DC sweep

本阶段选择纯电阻分压，而不是 MOS I-V。

原因：

- 电阻分压不依赖 PDK 或 MOS model；
- 理论关系非常稳定，便于写 deterministic 测试；
- 可以直接验证 `.dc`、`wrdata`、parser、session 和 evaluator 链路；
- 不会把“第二仿真器基础能力验证”拖成“模型库接入问题”。

电路：

```text
Vin -- Rtop -- out -- Rbottom -- 0
```

理论响应：

```text
v(out) = Vin * Rbottom / (Rtop + Rbottom)
```

默认参数：

| 参数 | 默认值 |
|---|---:|
| `top_resistance_ohm` | `1000 Ω` |
| `bottom_resistance_ohm` | `1000 Ω` |
| `dc_start_v` | `0 V` |
| `dc_stop_v` | `1 V` |
| `dc_step_v` | `0.1 V` |

## 新增 ResultIR

新增：

```cpp
struct DcSweep {
  std::string sweep_name;
  std::string signal;
  std::vector<double> sweep_values;
  std::vector<double> values;
};
```

它只表达一个 sweep axis 与一个实数 signal response。

本阶段没有直接引入多维 sweep、family curve、device operating point map 或单位系统。
这些结构应该等待 MOS I-V、gm/Id 或第二个真实 backend 的同类 DC sweep 需求出现后再扩展。

## 新增 Ngspice 内置任务

新增：

```cpp
enum class NgspiceBuiltinTask {
  kRcAc,
  kRcTran,
  kResistorDividerDc,
};
```

`kResistorDividerDc` 每次 run 会生成：

```text
resistor_divider_dc.cir
```

并调用：

```text
ngspice -b resistor_divider_dc.cir
```

输出：

```text
resistor_divider_dc.out
ngspice.log
```

## Netlist 形态

核心 netlist 形态：

```spice
Vin in 0 dc 0
Rtop in out <top_resistance_ohm>
Rbottom out 0 <bottom_resistance_ohm>
.control
set filetype=ascii
dc Vin <dc_start_v> <dc_stop_v> <dc_step_v>
wrdata resistor_divider_dc.out v(out)
quit
.endc
.end
```

本机 Ngspice 对该 netlist 的 `wrdata v(out)` 输出为两列：

```text
sweep_value value
```

示例：

```text
0.00000000e+00  0.00000000e+00
1.00000000e-01  5.00000000e-02
2.00000000e-01  1.00000000e-01
```

## 新增公开 API

```cpp
struct NgspiceResistorDividerDcConfig {
  double top_resistance_ohm = 1000.0;
  double bottom_resistance_ohm = 1000.0;
  double sweep_start_v = 0.0;
  double sweep_stop_v = 1.0;
  double sweep_step_v = 0.1;
};

NgspiceResistorDividerDcConfig ngspice_resistor_divider_dc_config_from_state(
    const ParameterState& state);

std::string render_ngspice_resistor_divider_dc_netlist(
    const NgspiceResistorDividerDcConfig& config,
    const std::string& output_filename = "resistor_divider_dc.out");

ReadResult<DcSweep> read_ngspice_wrdata_dc_sweep(
    const std::string& data_path,
    const std::string& sweep_name,
    const std::string& signal_name);
```

`ParameterState` key：

| key | 含义 |
|---|---|
| `top_resistance_ohm` | 上拉电阻 |
| `bottom_resistance_ohm` | 下拉电阻 |
| `dc_start_v` | `.dc` sweep 起点 |
| `dc_stop_v` | `.dc` sweep 终点 |
| `dc_step_v` | `.dc` sweep 步长 |

## 当前测试覆盖

默认测试覆盖：

- `DcSweep` shape consistency；
- `NgspiceResistorDividerDcConfig` 默认值与 `ParameterState` override；
- 电阻分压 `.dc` netlist 渲染；
- 两列 `wrdata` DC sweep parser；
- malformed / extra-column parser failure。

external 测试覆盖：

- `NgspiceSessionExternalTest.RunsResistorDividerDcWhenExternalNgspiceIsEnabled`；
- `NgspiceEvaluatorExternalTest.RunsDcBatchThroughEvaluatorWhenExternalNgspiceIsEnabled`。

外部测试会真实调用 Ngspice，并检查：

```text
v(out) ≈ Vin * Rbottom / (Rtop + Rbottom)
```

## 当前边界

- 当前只支持单 sweep axis、单 signal 的实数 DC sweep。
- 当前没有实现 `.op` operating point parser。
- 当前没有实现 MOS I-V family curve。
- 当前没有引入 Ngspice binary raw parser。
- 当前没有把 DC sweep 与 Spectre PSF sweep 做同类语义对照。

## 后续建议

短期不建议继续扩展 DC 抽象，除非出现明确消费者。

比较合理的后续选择有两个：

- 若只是完善多 backend 对照：增加 Spectre 侧同类电阻分压 DC sweep fixture；
- 若进入器件特性或 gm/Id：再引入 MOS I-V / family curve 形态，并评估 `DcSweep`
  是否需要扩展为多曲线结构。
