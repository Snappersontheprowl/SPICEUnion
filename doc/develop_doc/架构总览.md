更新时间：2026-08-13

1. 先看总体分层架构图，理解 M1 / M2 / M3 / M4 的位置。

4. 最后看模块责任图，理解目录和公开头文件的职责。

核心结论：

- M1 负责执行；
- M2 负责结果读取；
- M3 负责多 backend 和语义对照；
- M4 负责可选 Python 入口；
- OrderedConcurrentPool 是独立项目，SPICEUnion 通过 `SimulatorPool` adapter 装配。

## 2. 执行链路图

这张图回答：

- 一个 batch 如何从调用方进入 simulator；
- 为什么 `TaskResult` 只返回执行状态和 `work_dir`；
- 为什么结果解析不在 `Evaluator` 里。

```mermaid
sequenceDiagram
    autonumber

    participant Caller as 调用方
    participant Evaluator as Evaluator
    participant Pool as SimulatorPool adapter
    participant OCP as OrderedConcurrentPool
    participant Session as SimulatorSession
    participant Simulator as Spectre / Ngspice
    participant WorkDir as worker work_dir

    Caller->>Evaluator: run(vector<ParameterState>)
    Evaluator->>Pool: evaluate_batch(states)
    Pool->>OCP: submit ordered jobs

    loop 每个 ParameterState
        OCP->>Session: run(state, timeout)
        Session->>Simulator: 写参数 / 执行仿真
        Simulator->>WorkDir: 输出仿真结果文件
        Session-->>OCP: TaskResult(status, work_dir)
    end

    OCP-->>Pool: ordered vector<TaskResult>
    Pool-->>Evaluator: ordered vector<TaskResult>
    Evaluator-->>Caller: ordered vector<TaskResult>
```

执行层边界：

- `Evaluator` 保证 batch 输出和输入等长同序；
- 每个 worker 使用独立 `work_dir`；
- 单任务失败只影响对应 `TaskResult`；
- `TaskResult` 不承载 waveform、metric、objective 或 score；
- 调用方拿到成功的 `work_dir` 后，再进入结果读取链路。

## 3. 结果读取链路图

这张图回答：

- 仿真结束后，结果文件如何变成 C++ ResultIR；
- libpsf 在哪里；
- Python binding 包装了什么；
- Ngspice 文本结果如何进入同一套 ResultIR。

```mermaid
flowchart LR

    PsfFiles["Spectre PSF 文件<br/>dcOp.dc / dc.dc / ac.ac / tran.tran"]
    NgspiceOut["Ngspice wrdata 文本<br/>rc_ac.out / rc_tran.out / resistor_divider_dc.out"]

    Reader["result_reader.hpp<br/>公开读取 helper"]

    TextParser["Ngspice wrdata parser"]
    ResultIR["ResultIR<br/>ScalarResult<br/>DcSweep<br/>AcResponse<br/>TranWaveform"]
    Math["数学 helper<br/>derive_ac_view<br/>UGBW / PM<br/>settling time"]
    Py["Python binding<br/>spiceunion module"]

    WorkDir --> RawDir
    RawDir --> PsfFiles
    WorkDir --> NgspiceOut

    Reader --> Libpsf
    Reader --> TextParser

    Libpsf --> PsfFiles
    TextParser --> NgspiceOut

    Libpsf --> ResultIR
    TextParser --> ResultIR
    ResultIR --> Math
    Reader --> ResultIR
    Py --> Reader
    Py --> ResultIR
    Py --> Math
```

结果层边界：

- libpsf 是内部可选 backend；
- 公开 API 不暴露 libpsf 类型；
- Python binding 不重新实现解析逻辑，只包装 C++ `result_reader.hpp` 和 ResultIR；
- `ReadResult<T>` 明确表达成功、失败状态和错误消息；
- 读取失败不能伪装成 `0.0`、空数组或 `None`。

这张图回答：

- 仓库主要目录分别负责什么；

```mermaid

```

模块责任边界：

- `include/su` 是公开 C++ API；
- `src/core` 和 `src/pool` 是执行层实现；
- `src/session` 拥有外部 simulator process/protocol 细节；
- `src/parse` 拥有结果读取实现；
- `bindings/python` 是可选语言绑定，不反向影响默认 C++ 构建；
- `doc/develop_doc` 保存长期有效开发文档。
