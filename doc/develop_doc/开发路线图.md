# SPICEUnion 开发路线图

更新时间：2026-08-11

本文是 SPICEUnion 的施工路线，只记录与当前主线直接相关的后续任务。项目章程见 `CPP版本开发计划书.md`；当前事实和测试结果见 `当前事实状态.md`。

## 1. 当前主线

SPICEUnion 后续只围绕这条朴素链路收敛：

```text
给定 netlist
  -> 选择对应仿真器
  -> 准备工作目录
  -> 执行仿真
  -> 返回执行状态与结果目录
  -> 按需要读取结果
```

当前不设计完整 netlist IR，不做 SPICE 方言转换，不引入业务分析 DSL。

## 3. 当前后续任务

### 3.1 最小外部 netlist 执行入口评估

目标：

- 支持用户给定一个已有 netlist；
- 由调用方明确选择仿真器；
- SPICEUnion 负责准备工作目录、执行仿真、返回 `TaskResult` 与结果目录；
- 不解析网表；
- 不设计完整 netlist IR；
- 不做跨仿真器方言转换。

建议第一版输入只包含：

```text
simulator kind
netlist path
workspace / work directory
timeout
```

完成定义：

- 能用最小入口执行一个外部 Spectre 或 Ngspice netlist；
- 不改变现有 `Evaluator` 保序和失败隔离语义；
- 默认测试不依赖真实仿真器；
- external 测试在依赖缺失时 skip；
- README 与 `当前事实状态.md` 同步更新。

### 3.2 必要结果读取 fixture 补充

目标：

- 只根据真实 netlist 输出补充 fixture；
- 结果读取继续复用当前最小 ResultIR；
- 不为假想 MOS、gm/Id、多维 sweep 或业务分析扩展 ResultIR。

当前可优先评估：

- 若外部 Spectre DC sweep netlist 成为真实样例，则验证其结果是否能映射到现有 `DcSweep`；
- 若无法映射，先记录格式边界，不立即扩展 ResultIR。

完成定义：

- fixture 小型、可提交、无 PDK 依赖；
- 默认构建不依赖外部 EDA 工具；
- 结果读取失败语义明确；
- `当前事实状态.md` 记录真实能力与边界。

## 4. 当前明确不做

以下内容不属于当前主线，除非用户重新明确改变项目目标：

- 完整 netlist IR；
- SPICE 方言转换；
- analysis / probe DSL；
- MOS I-V / gm/Id 设计方法；
- optimizer；
- C ABI / Python / MATLAB binding；
- Xyce / Hspice backend 扩展；
- 为假想场景提前扩展 ResultIR；
- 为假想场景提前扩展 `EvaluatorOptions`。

## 5. 验证矩阵

| 场景 | 命令 |
|---|---|
| 默认开发验证 | `cmake --preset default && cmake --build --preset default && ctest --preset default --output-on-failure` |
| 外部 Spectre / Ngspice 验证 | `cmake --preset external && cmake --build --preset external && ctest --preset external --output-on-failure` |
| libpsf backend 验证 | `cmake -S . -B cmake-build-libpsf -DCMAKE_BUILD_TYPE=Debug -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -DSPICEUNION_BUILD_TESTS=ON -DSPICEUNION_ENABLE_EXTERNAL_TESTS=OFF -DSPICEUNION_ENABLE_LIBPSF_READER=ON && cmake --build cmake-build-libpsf && ctest --test-dir cmake-build-libpsf --output-on-failure` |

最近验证结果不在本文件维护，统一见 `当前事实状态.md`。

## 6. 文档更新规则

新增或变更能力时：

1. 更新根 `README.md` 的当前能力或边界。
2. 更新 `当前事实状态.md`。
3. 若影响施工顺序、进入条件或完成定义，更新本路线图。
4. 若影响项目范围或设计原则，更新 `CPP版本开发计划书.md`。
5. 若影响公开 API，更新 `include/su/README.md`。
6. 若影响测试结构，更新 `tests/README.md`。

完成修改后按项目约定进行本地 `git commit`。
