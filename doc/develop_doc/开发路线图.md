## 2. 当前后续任务与暂缓方向

### 2.1 Spectre 侧 DC sweep 对照（已完成）

详细现状、选项和执行切分见 `M3.md`。

目标：

- 增加 Spectre 电阻分压 DC sweep fixture；
- 验证 Spectre PSF DC sweep 是否能映射到现有 `DcSweep`；
- 不引入 MOS 模型依赖。

预期产出：

- Spectre 源 netlist fixture；
- 固化 PSF fixture；
- `DcSweep` 语义对照测试；
- `当前事实状态.md` 更新。

完成定义：

- 默认构建不依赖 Spectre；
- libpsf 构建下能读取 Spectre DC sweep fixture；
- external 构建下 Ngspice DC sweep 仍通过；
- Spectre / Ngspice DC sweep 复用同一套语义检查。

暂缓条件：

- 当前没有跨 backend DC sweep 消费者；
- libpsf 无法读取目标 Spectre DC sweep 格式；
- fixture 会引入 PDK 或模型依赖。

### 2.2 MOS I-V / gm/Id 需求评估（暂缓）

目标：

- 判断 `DcSweep` 是否足够表达 MOS I-V；
- 若出现 family curve 需求，再设计多曲线 DC ResultIR。

不得提前做：

- 不提前引入 MOS 模型库；
- 不提前引入多维 sweep；
- 不把 gm/Id lookup table 写进 SPICEUnion core。

完成定义：

- 有真实消费者；
- 有至少一个真实 backend 输出样本；
- 新 ResultIR 有测试覆盖；
- README 与 `当前事实状态.md` 同步更新。

### 2.3 EvaluatorOptions / netlist template 扩展（暂缓）

进入条件：

- Spectre 与 Ngspice 两个 backend 都需要同类配置能力；
- 现有 `ParameterState` 与内置任务枚举无法表达真实需求。

不得提前做：

- 不为了未来仿真器设计完整 request IR；
- 不把 netlist 生成器变成项目业务 DSL；
- 不破坏现有 `Evaluator` 输入保序与 failure isolation 契约。

## 4. 验证矩阵

| 场景 | 命令 |
|---|---|
| 默认开发验证 | `cmake --preset default && cmake --build --preset default && ctest --preset default --output-on-failure` |
| 外部 Spectre / Ngspice 验证 | `cmake --preset external && cmake --build --preset external && ctest --preset external --output-on-failure` |
| libpsf backend 验证 | `cmake -S . -B cmake-build-libpsf -DCMAKE_BUILD_TYPE=Debug -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -DSPICEUNION_BUILD_TESTS=ON -DSPICEUNION_ENABLE_EXTERNAL_TESTS=OFF -DSPICEUNION_ENABLE_LIBPSF_READER=ON && cmake --build cmake-build-libpsf && ctest --test-dir cmake-build-libpsf --output-on-failure` |
| Python binding 验证 | `cmake -S . -B cmake-build-python -DCMAKE_BUILD_TYPE=Debug -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -DSPICEUNION_BUILD_TESTS=ON -DSPICEUNION_BUILD_PYTHON_BINDINGS=ON && cmake --build cmake-build-python && ctest --test-dir cmake-build-python --output-on-failure` |
| Python binding + libpsf 验证 | `cmake -S . -B cmake-build-python-libpsf-pic -DCMAKE_BUILD_TYPE=Debug -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -DSPICEUNION_BUILD_TESTS=ON -DSPICEUNION_BUILD_PYTHON_BINDINGS=ON -DSPICEUNION_ENABLE_LIBPSF_READER=ON && cmake --build cmake-build-python-libpsf-pic && ctest --test-dir cmake-build-python-libpsf-pic --output-on-failure` |

最近验证结果不在本文件维护，统一见 `当前事实状态.md`。

## 5. 文档更新规则

新增或变更能力时：

1. 更新根 `README.md` 的当前能力或边界。
2. 更新 `当前事实状态.md`。
3. 若影响施工顺序、进入条件或完成定义，更新本路线图。
4. 若影响项目范围或设计原则，更新 `CPP版本开发计划书.md`。
5. 若影响公开 API，更新 `include/su/README.md`。
6. 若影响测试结构，更新 `tests/README.md`。
7. 若影响 OrderedConcurrentPool 专项边界，更新 `OrderedConcurrentPool开发路线图.md`。
8. 若影响 C ABI / pybind11 接入策略，更新 `M4.md`。
9. 若影响 M3 多仿真器接入或结果语义收敛策略，更新 `M3.md`。

完成修改后按项目约定进行本地 `git commit`。
