# SPICEUnion 当前事实状态

更新时间：2026-09-02

## 项目定位

SPICEUnion 是 C++17 仿真器执行与结果读取基础设施库。

| 范围内 | 范围外 |
|---|---|
| batch 参数状态执行 | circuit metric / objective / penalty |
| worker 工作目录隔离 | optimizer |
| 输入顺序保序返回 | PDK 内容管理 |
| C++ 用户工作流 facade | GUI |
| Spectre interactive backend | 分布式调度 |
| Ngspice batch backend | 完整 netlist IR |
| 最小 ResultIR 与结果读取 helper | Hspice / Xyce backend |

## 当前已实现能力

### 执行层

- `Evaluator` 支持 batch execution facade。
- batch 结果按输入顺序返回。
- worker 使用独立 work directory。
- 单任务失败不会破坏其他任务结果。
- startup failure、timeout、transport failure、simulation failure 有标准 `TaskStatus`。
- SPICEUnion 通过 `SPICEUNION_ORDERED_POOL_SOURCE_DIR` 装配外部
  `~/my_lab/projects/OrderedConcurrentPool` 项目。
- `spiceunion_core` 链接 `ocp::ordered_concurrent_pool`。
- `SimulatorPool` 已改为 SPICEUnion adapter，负责把 `EvaluatorOptions`、
  `SessionFactory`、`ParameterState`、`TaskResult` 与 `SimulatorSession` 映射到
  `OrderedConcurrentPool`。
- `~/my_lab/projects/OrderedConcurrentPool` 已创建为独立项目：
  - C++17 header-only；
  - CMake target 为 `ocp::ordered_concurrent_pool`；
  - 包含 `include/ocp/ordered_concurrent_pool.hpp`；
  - 包含 GoogleTest 契约测试；
  - 包含 `examples/basic_batch.cpp` 最小示例；
  - 包含 `benchmarks/ordered_pool_benchmark.cpp` 最小基准程序；
  - license 已明确为 MIT；
  - 已记录 `CHANGELOG.md`；
  - 已将 `main` 与 `v0.1.0` tag 发布到 `origin`；
  - 已增加 GitHub Actions CI；

  - graceful / force stop。

### 用户工作流层

当前已实现 C++ workflow facade：

- 公开头文件：`include/su/workflow.hpp`；
- 实现目录：`src/workflow/`；
- 用户主入口：`Simulation`；
- 单任务结果 facade：`SimulationResult`；
- 配置类型：`SimulationOptions`；
- 单 case 参数映射：`SimulationCase`；
- simulator 选择：`SimulatorKind::kSpectre` / `SimulatorKind::kNgspice`；
- 当前 Ngspice workflow 仍复用 `NgspiceBuiltinTask` 内置任务；
- `Simulation` 支持声明必填参数和带默认值参数；
- `run()` 在启动底层 evaluator 前拒绝未声明参数、缺失必填参数和非 finite 参数；
- batch 输出保持输入顺序；
- 单任务失败封装为 `SimulationResult`，不污染同批其他结果；
- `SimulationResult` 提供 `read_dc()`、`read_dc_sweep()`、`read_ac()`、`read_tran()`；
- 成功任务可通过 `SimulationResult` 自动使用 `TaskResult.work_dir` 和
  `TaskResult.result_format` 读取结果；
- `work_dir()` 与 `result_format()` 保留为高级诊断字段，不作为普通读取主路径；
- `make_simulation_for_session_factory()` 提供测试与高级嵌入入口。

当前边界：

- Python workflow binding 尚未实现；
- MATLAB binding 尚未实现；
- 不实现 optimizer、netlist DSL、PDK 管理、GUI 或业务 metric；
- Ngspice 仍是内置教学级 batch 任务，不代表完整 Ngspice 任意网表支持。

|---|---|

`src/parse/psf_ascii_backend.cpp`，BINPSF 走可选 libpsf；`SPICEUNION_ENABLE_LIBPSF_READER`

格式声明：`ResultFormat` 作为执行契约（`EvaluatorOptions.result_format` /
`TaskResult.result_format`）。执行层仿真完成后交付实际格式——Spectre 按
netlist `rawfmt` / 调用方声明得到请求格式，再按产物特征确认（存在 `*.psfxl`
则标 `kPsfxl`，AMP/tran 实测即由运行期确认为 PSFXL）；Ngspice 成功结果标
`kNspiceWrdata`。解析层声明优先，`kUnknown` 才回退嗅探。
