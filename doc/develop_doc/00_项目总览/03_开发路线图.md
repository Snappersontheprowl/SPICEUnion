## 2. 最近完成阶段

### 2.1 Python workflow binding

状态：第一版已完成。阶段记录见
`../10_阶段记录/06_M6_Python工作流Binding.md`，API 细节见
`../20_专题记录/03_Python工作流Binding设计.md`。

目标：让 Python 用户能够直接启动批量仿真，而不是只读取已有结果。Python 入口应绑定
workflow 层，而不是直接暴露底层 `SimulatorSession`、`SessionFactory` 或
`OrderedConcurrentPool`。

已满足前置条件：

- C++ workflow API 已完成并有默认契约测试覆盖。
- Python result 对象已有稳定包装和失败语义。
- 入口边界已确认：绑定 workflow facade，不绑定底层执行对象。

已落实：

- Python `Simulation.cleanup()`、析构和 context manager 的关系。
- 默认 Python preset 与外部 EDA 工具 smoke test 的门控切分。
- `SimulationResult.read_*()` 如何复用现有 Python result 包装对象。

完成定义：

- Python 可创建 simulation、声明参数、提交 `list[dict[str, float]]` 并获取结果对象。
- Python 结果对象复用当前 `ok()`、`status_text()`、`message` 失败语义。
- CTest 覆盖 import、API contract、无外部依赖的 workflow 输入契约和可跳过的 Ngspice workflow smoke。

### 2.2 工具链自动适配与诊断（MVP）

`01_当前事实状态.md`「工具链探测（MVP）」。

- 验证：ToolchainTest 5/5、default 102/102、external-libpsf
  spectre/ngspice 子集 10/10。

## 3. 候选后续阶段

### 3.1 结果格式能力扩展

候选方向：

- Spectre 23.1 PSFXL transient 解析或转换路径。
- 原生 PSF parser。
- legacy sensitivity 读取。
- libpsf backend 产品化分发与 license notice。

进入条件：

- 有真实 fixture 或真实消费者。
- 能明确和现有 `ResultIR` 的关系。
- 能用默认测试或可选预设钉住失败语义。

### 3.2 仿真器与结果模型扩展

候选方向：

- Ngspice `.op` operating point。
- MOS I-V / gm/Id 多曲线 DC 结果。
- Xyce / Hspice backend。

进入条件：

- 有合法网表样本和固定 fixture。
- 现有 `ScalarResult`、`DcSweep`、`AcResponse`、`TranWaveform` 无法表达真实需求。
- 新 backend 或 ResultIR 不把业务 metric / objective / optimizer 写进 core。

### 3.3 工具链自动适配与诊断（后续扩展）

MVP 已完成（见 2.2），以下候选继续项仍适用（完成定义与边界见专题文档
`../20_专题记录/04_仿真器自动适配与诊断设计.md`）：

- 版本→能力门控与机器可读错误分类；
- Spectre 安全版本探测策略；
- Python `doctor()` / 自动装配。

## 5. 验证矩阵

| 场景 | 命令 |
|---|---|
| 默认开发验证 | `cmake --preset default && cmake --build --preset default && ctest --preset default --output-on-failure` |
| 外部 Spectre / Ngspice 验证 | `cmake --preset external && cmake --build --preset external && ctest --preset external --output-on-failure` |
| libpsf backend 验证 | `cmake --preset libpsf && cmake --build --preset libpsf && ctest --preset libpsf --output-on-failure` |
| Python binding 验证 | `cmake --preset python && cmake --build --preset python && ctest --preset python --output-on-failure` |
| Python binding + libpsf 验证 | `cmake --preset python-libpsf-pic && cmake --build --preset python-libpsf-pic && ctest --preset python-libpsf-pic --output-on-failure` |

最近验证结果不在本文件维护，统一见 `01_当前事实状态.md`。
