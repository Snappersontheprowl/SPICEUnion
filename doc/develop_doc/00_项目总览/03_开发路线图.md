## 2. 候选下一阶段

### 2.1 统一用户工作流 API

目标：提供面向普通用户的 `Simulation` / `SimulationResult` 层，让 C++、Python、未来
MATLAB 入口共享同一套使用逻辑：

```text
用户提供合法网表
  -> 用户声明可变参数
  -> 用户提交参数组合并启动仿真
  -> 用户基于结果对象读取信号
  -> 用户搭建上层指标提取
```

内部并行、backend class、worker directory、`.raw`、PSF / wrdata 解析细节不作为普通用户主路径暴露。

进入条件：

- 明确第一版只做 workflow facade，不实现 optimizer、netlist DSL 或业务 metric 系统。
- 明确 C++ API 先落地，Python binding 绑定 workflow API，而不是直接扩大底层 session binding。
- 明确 `Evaluator`、`TaskResult`、`result_reader` 继续作为内部或高级 API 复用，不推倒重写。

完成定义：

- 新增公开 C++ workflow API 与契约测试。
- 普通用户可以不直接调用 `find_result_directory()` 即读取成功任务的 DC / AC / TRAN 结果。
- 根 README 主示例切换到 workflow API。
- `01_当前事实状态.md`、`02_架构总览.md`、`include/su/README.md`、`src/README.md` 同步更新。

暂缓条件：

- 真实用户仍只需要底层 C++ 嵌入接口。
- workflow API 无法在 Spectre 和 Ngspice 之间形成稳定公共语义。
- 参数声明、默认值和非法 case 的失败语义尚未收口。

### 2.2 Python 执行层 binding

目标：让 Python 用户能够直接启动批量仿真，而不是只读取已有结果。

推荐前置条件：

- C++ workflow API 已落地。
- Python 绑定只暴露 workflow 层和结果层，不暴露 `SimulatorSession`、`SessionFactory`、
  `OrderedConcurrentPool` 等内部细节。

完成定义：

- Python 可创建 simulation、声明参数、提交 `list[dict[str, float]]` 并获取结果对象。
- Python 结果对象复用当前 `ok()`、`status_text()`、`message` 失败语义。
- CTest 覆盖 import、API contract 和最小执行层 smoke。

### 2.3 结果格式能力扩展

候选方向：

- Spectre 23.1 PSFXL transient 解析或转换路径。
- 原生 PSF parser。
- legacy sensitivity 读取。
- libpsf backend 产品化分发与 license notice。

进入条件：

- 有真实 fixture 或真实消费者。
- 能明确和现有 `ResultIR` 的关系。
- 能用默认测试或可选预设钉住失败语义。

### 2.4 仿真器与结果模型扩展

候选方向：

- Ngspice `.op` operating point。
- MOS I-V / gm/Id 多曲线 DC 结果。
- Xyce / Hspice backend。

进入条件：

- 有合法网表样本和固定 fixture。
- 现有 `ScalarResult`、`DcSweep`、`AcResponse`、`TranWaveform` 无法表达真实需求。
- 新 backend 或 ResultIR 不把业务 metric / objective / optimizer 写进 core。

## 4. 验证矩阵

| 场景 | 命令 |
|---|---|
| 默认开发验证 | `cmake --preset default && cmake --build --preset default && ctest --preset default --output-on-failure` |
| 外部 Spectre / Ngspice 验证 | `cmake --preset external && cmake --build --preset external && ctest --preset external --output-on-failure` |
| libpsf backend 验证 | `cmake --preset libpsf && cmake --build --preset libpsf && ctest --preset libpsf --output-on-failure` |
| Python binding 验证 | `cmake --preset python && cmake --build --preset python && ctest --preset python --output-on-failure` |
| Python binding + libpsf 验证 | `cmake --preset python-libpsf-pic && cmake --build --preset python-libpsf-pic && ctest --preset python-libpsf-pic --output-on-failure` |

最近验证结果不在本文件维护，统一见 `01_当前事实状态.md`。
