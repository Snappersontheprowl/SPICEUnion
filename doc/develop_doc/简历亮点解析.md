## 1. 一句话定位

SPICEUnion 是一个 C++17 仿真器执行与结果读取基础设施库，主线逻辑是：

```text
给定 netlist
  -> 选择仿真器
  -> 执行仿真
  -> 返回状态与结果目录
  -> 按需要读取结果
```

当前已落地 Spectre interactive backend、Ngspice batch backend、最小 ResultIR、结果读取 helper 和保序 batch 调度。

## 2. 可粘贴项目条目

> **SPICEUnion — C++17 仿真器执行与结果读取基础设施**
>
> - 对齐既有 Python `spectre_interactive` 执行语义，重写 batch evaluator，保持 worker 工作目录隔离、输入保序返回和单任务失败隔离；
> - 抽象 `SimulatorSession`，落地 Spectre interactive 与 Ngspice batch 两个真实 backend；
> - 设计最小 ResultIR，覆盖 scalar、AC response、transient waveform 和 DC sweep 等基础结果结构；
> - 将 libpsf 封装为可选内部 backend，公开 API 不暴露第三方库类型；
> - 从 SPICEUnion 调度需求中提取 `OrderedConcurrentPool` 独立 C++17 header-only 库，完成 MIT 发布、CMake install/export、benchmark 与 GitHub Actions CI。

## 3. 真实亮点

| 亮点 | 能证明什么 | 事实依据 |
|---|---|---|
| 保序 batch evaluator | 并发调度、失败隔离、工作目录隔离 | default / external 测试通过 |
| Spectre + Ngspice 双 backend | 抽象不是空想，已被两个真实执行路径验证 | Spectre interactive、Ngspice batch |
| 最小 ResultIR | 结果建模克制，只表达读取结果，不承载业务指标 | `ScalarResult`、`AcResponse`、`TranWaveform`、`DcSweep` |
| 可选 libpsf backend | 第三方依赖隔离，公开 API 稳定 | `SPICEUNION_ENABLE_LIBPSF_READER=ON` |
| OrderedConcurrentPool 独立化 | 从真实消费者提取通用基础库 | OCP `v0.1.0`、MIT、CI |

## 4. 推荐讲法

### 4.1 主线讲法

先讲朴素流程：

```text
给网表
  -> 选仿真器
  -> 跑
  -> 拿结果目录
  -> 读结果
```

再解释为什么需要少量抽象：

- `SimulatorSession`：隔离 Spectre interactive 和 Ngspice batch 的执行差异；
- `TaskResult`：统一表达执行成功、失败、超时和结果目录；
- `ResultIR`：统一读取后的结果结构；
- `OrderedConcurrentPool`：复用 batch 并发、输入保序和失败隔离逻辑。

重点是：

```text
抽象服务于这条简单链路，不为了未来幻想设计大框架。
```

### 4.2 OrderedConcurrentPool 讲法

可以说：

```text
我先在 SPICEUnion 里实现保序并发 worker pool，等语义被真实使用验证后，再把它提取成领域无关的独立 C++17 header-only 库。
```

可讲事实：

- 固定 worker；
- batch 并发执行；
- 输入保序返回；
- per-job exception 转换；
- startup failure cleanup；
- repeated shutdown；
- CMake package；
- MIT license；
- GitHub Actions CI；
- ASan / TSan 验证。

## 5. 红线

简历或面试里不要写：

- 支持 Hspice / Xyce；
- 已有 C ABI / Python / MATLAB binding；
- 已有完整 netlist IR；
- 已有 SPICE 方言转换；
- 已有 MOS I-V / gmId 设计能力；
- 已有 native PSF parser；
- 已有可承诺的性能提升倍数；
- OrderedConcurrentPool 支持动态扩缩容、取消、重试、优先级或无锁队列。

可以写：

- 当前支持 Spectre interactive 与 Ngspice batch 的基础执行路径；
- 当前具备最小 ResultIR 与 fixture 驱动验证；
- 当前 OCP 已独立发布并具备 CI；
- 当前性能 benchmark 只用于本机回归观察，不作为跨机器承诺。
