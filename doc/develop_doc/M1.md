# M1 Spectre 执行层开发文档

更新时间：2026-08-13

本文负责 SPICEUnion M1 阶段的现状总结、责任边界和收口事实。

当前结论：

```text
M1 已完成；
Evaluator facade、SimulatorSession 抽象、TaskResult 执行状态、Spectre interactive backend 与 batch 保序契约已建立；
后续 M3.5 将通用有序并发池抽离为 OrderedConcurrentPool，SPICEUnion 当前通过 SimulatorPool adapter 装配；
结果读取、Ngspice backend、Python binding 与 C ABI 均不属于 M1。
```

## 1. M1 目标

M1 的目标是把 Python 版 `spectre_materials` 中的 Spectre interactive 执行链路，用 C++17 建立为可测试、可嵌入的执行层基础。

行为基线来自：

- `~/my_lab/projects/spectre_materials/src/spectre_interactive/generic_evaluator.py`
- `~/my_lab/projects/spectre_materials/src/spectre_interactive/daemon_pool.py`
- `~/my_lab/projects/spectre_materials/src/spectre_interactive/spectre_daemon.py`
- `~/my_lab/projects/spectre_materials/src/spectre_interactive/task_library.py`

M1 关注：

- `ParameterState` batch 输入；
- `EvaluatorOptions` 执行配置；
- `Evaluator` batch facade；
- `SimulatorSession` 生命周期抽象；
- `TaskResult` 执行状态；
- worker 工作目录隔离；
- 输入顺序保序返回；
- 单任务失败隔离；
- Spectre `+interactive` handshake、参数写入和 `(sclRun "all")`；
- startup / timeout / transport / simulation failure 的执行状态表达。

M1 不关注：

- PSF 结果解析；
- ResultIR；
- libpsf backend；
- Ngspice / Hspice / Xyce；
- Python binding；
- C ABI；
- optimizer；
- circuit metric / objective / penalty；
- 完整 netlist IR。

## 2. M1 范围边界

### 2.1 范围内

- 定义执行层共享输入类型；
- 定义任务执行状态；
- 建立 session 抽象；
- 建立 Spectre interactive session backend；
- 建立 evaluator batch runner；
- 保障 worker work directory 可定位；
- 保障 batch 输出和输入等长同序；
- 保障单任务失败不破坏其他任务；
- startup failure 时清理已创建 worker；
- 用 fake/scripted session 做默认契约测试；
- 外部 Spectre 测试默认关闭，显式启用后才运行。

### 2.2 范围外

- 不在 `TaskResult` 中塞入解析后的波形或 metric；
- 不在 `Evaluator::run()` 中接收 Python 风格 `parse_func`；
- 不把结果解析耦合进执行层；
- 不在 M1 设计多仿真器统一 netlist DSL；
- 不在 M1 处理第二仿真器；
- 不在 M1 处理跨语言接口。

## 3. 当前已完成事实

### 3.1 `core.hpp`

当前公开类型：

| 类型 | 含义 |
|---|---|
| `ParameterState` | 单个仿真状态的参数映射，当前为 `std::map<std::string, double>` |
| `EvaluatorOptions` | evaluator/session 配置，包括 netlist、worker 数量、工作目录、namespace、timeout 与 restart_attempts |

`EvaluatorOptions` 当前字段：

| 字段 | 含义 |
|---|---|
| `netlist_path` | 仿真器输入 netlist 路径 |
| `num_workers` | worker 数量，默认 16 |
| `work_dir_base` | worker 工作目录根路径，默认 `local/runtime/workers`（相对调用方 cwd） |
| `workspace_namespace` | evaluator 工作区 namespace；为空时自动生成 |
| `timeout_seconds` | 单任务 timeout，默认 60 |
| `restart_attempts` | restart 尝试次数配置；当前保留在 options 中 |

### 3.2 `TaskResult`

当前执行状态：

| 状态 | 含义 |
|---|---|
| `kSuccess` | 任务执行成功 |
| `kSimulationFailed` | 仿真器报告仿真失败 |
| `kStartupFailed` | worker 或仿真器启动失败 |
| `kTimeout` | 单任务执行超时 |
| `kTransportFailure` | 与仿真器进程通信失败 |
| `kException` | C++ 层异常或未分类失败 |

`TaskResult` 当前字段：

- `status`
- `work_dir`
- `error_code`
- `error_message`
- `detail`

执行层原则：

- 成功时把 `work_dir` 返回给调用方；
- 失败时保留对应任务槽位的失败状态；
- `TaskResult` 不承载业务 metric；
- `TaskResult` 不承载 ResultIR；
- 结果读取由调用方在拿到 `work_dir` 后自行进行。

### 3.3 `SimulatorSession`

当前抽象接口：

| 方法 | 含义 |
|---|---|
| `start()` | 启动并准备一个 simulator worker |
| `run(state, timeout)` | 运行单个 `ParameterState` |
| `stop(graceful)` | 停止并释放 worker |
| `worker_id()` | 返回 worker id |
| `work_dir()` | 返回 worker 工作目录 |

该抽象是 M1 的关键切分点：调度层只依赖 `SimulatorSession`，具体 Spectre protocol 细节留在 `SpectreSession`。

### 3.4 `Evaluator`

当前事实：

- `Evaluator` 是 batch execution facade；
- 构造时创建并启动 simulator pool；
- `run(states)` 返回与输入 `states` 等长同序的 `TaskResult`；
- `run({})` 返回空结果；
- `worker_work_dirs()` 暴露 worker 目录；
- `cleanup()` 可重复调用；
- `reload_workers()` 会先 shutdown 再 start；
- `make_spectre_evaluator(options)` 提供 Spectre-backed evaluator 便捷构造。

当前边界：

- `Evaluator` 只返回执行状态；
- 不接收 parser callback；
- 不直接读取 PSF；
- 不计算业务指标；
- Python binding 当前不绑定 `Evaluator`。

### 3.5 `SimulatorPool`

M1 建立的核心契约：

- worker 数量必须有效；
- `SessionFactory` 必须有效；
- 每个 worker 有独立 work directory；
- `start_all()` 启动全部 worker；
- startup failure 时停止已创建 worker；
- `evaluate_batch(states)` 保序返回；
- 单任务失败不影响其他任务；
- task exception 转换为 `TaskResult` failure；
- `shutdown_all()` 可重复调用。

当前实现事实：

- M3.5 后，通用有序并发池已抽离到 `~/my_lab/projects/OrderedConcurrentPool`；
- SPICEUnion 当前的 `SimulatorPool` 是 adapter；
- adapter 负责把 `EvaluatorOptions`、`SessionFactory`、`ParameterState`、`TaskResult` 与 `SimulatorSession` 映射到 `ocp::ordered_concurrent_pool`；
- M1 的执行层契约仍由 SPICEUnion contract tests 覆盖。

## 4. Spectre interactive backend

### 4.1 `spectre_protocol.hpp`

当前职责：

- `format_spectre_run_command(state)`；
- `classify_spectre_completion_line(line, seen_resource_stats)`；
- `SpectreCompletion` 完成状态分类。

已验证：

- 参数写入命令格式；
- `(sclRun "all")` 命令；
- resource statistics 后 `t` 表示成功；
- resource statistics 后 `nil` 表示失败；
- 经典 `spectre completes ... 0 errors` 行表示成功。

### 4.2 `SpectreSession`

当前职责：

- 准备 worker directory；
- 使用 `spectre +interactive -64 -o <work_dir>` 启动 Spectre；
- 等待 SKILL interactive handshake；
- 使用 `(setq top (sclGetCircuit ""))` 初始化 circuit handle；
- 写入 `ParameterState`；
- 执行 `(sclRun "all")`；
- 等待 completion；
- 处理 timeout、`nil`、EOF、transport failure；
- 保留最近 stdout 行用于错误诊断；
- graceful stop，必要时 force stop。

当前外部 Spectre 测试覆盖：

- start / handshake / stop；
- single task run；
- `make_spectre_evaluator()` multi-worker batch。

外部测试默认关闭，需显式开启：

```text
SPICEUNION_ENABLE_EXTERNAL_TESTS=ON
```

## 6. M1 与后续阶段的关系

M1 建立执行层基础；后续阶段在它上面扩展。

| 阶段 | 与 M1 的关系 |
|---|---|
| M2 | 在 M1 返回的 `work_dir` 基础上建立结果读取层 |
| M3 | 复用 M1 的 `Evaluator` / `SimulatorSession` / `TaskResult` 接入 Ngspice backend |
| M3.5 | 将通用有序并发池从 SPICEUnion 中抽离为独立 `OrderedConcurrentPool` |
| M4 | 暂不绑定 M1 执行层，只绑定结果读取 helper |

后续演进事实：

- `NgspiceSession` 后续实现了同一个 `SimulatorSession` 接口；
- `OrderedConcurrentPool` 后续承担领域无关的有序并发池职责；
- `SimulatorPool` 当前保留为 SPICEUnion adapter；
- Python binding 当前不暴露执行层对象。

## 8. 暂缓项说明

### 8.1 结果解析

状态：不属于 M1。

原因：

- M1 执行层只返回 `TaskResult` 与 `work_dir`；
- 结果解析由 M2 负责；
- 该切分避免执行层和业务解析耦合。

### 8.2 多仿真器 backend

状态：不属于 M1。

原因：

- M1 只要求 Spectre backend 打通；
- 第二仿真器 Ngspice 由 M3 负责。

### 8.3 执行层 Python binding

状态：暂缓。

原因：

- 执行层存在进程生命周期、worker pool、timeout 和 cleanup 语义；
- 过早绑定会扩大 API 稳定负担；
- M4 当前只绑定结果读取 helper。

### 8.4 动态调度框架扩张

状态：暂缓。

原因：

- 当前 `Evaluator` / `SimulatorPool` / `OrderedConcurrentPool` 已覆盖保序 batch 需求；
- 没有真实消费者前，不扩展成通用分布式调度或完整 job system。
