# M4 pybind11 与 C ABI 接入开发文档

更新时间：2026-08-12

本文负责 SPICEUnion M4 阶段的开发规划与状态收口。

当前结论：

```text
M4.0 接入决策已收口；
M4.1 可以从 pybind11 最小结果读取绑定开始；
C ABI 不进入第一版实现，仅保留 ownership 草案。
```

## 1. M4 目标

M4 的目标是让 SPICEUnion 的 C++ 能力以稳定、可测试、低负担的方式暴露给外部调用方。

当前第一调用方按 Python 处理。C ABI 只作为后续跨语言或稳定二进制接口需求出现时的扩展方向。

## 2. 已确认开发基线

| 事项 | M4 基线 |
|---|---|
| 第一实现路线 | 先 pybind11，后 C ABI |
| 第一版绑定范围 | 只绑定结果读取 helper 和少量基础结果类型 |
| Python 模块名 | `spiceunion` |
| binding 源码目录 | `bindings/python/` |
| Python 返回值形态 | class / dataclass 风格 |
| 数值数组 | 第一版使用普通 Python 容器，暂不引入 numpy |
| 测试入口 | 先用 CTest 调 Python |
| CMake 开关 | 默认关闭 Python binding 和 C ABI |
| `Evaluator` binding | 第一版不绑定，后续评估 |
| C ABI | 第一版不实现，只保留 ownership 草案 |

## 3. M4 范围

### 3.1 范围内

- 建立 pybind11 最小绑定；
- 暴露稳定的结果读取接口；
- 明确 C++ ResultIR 到 Python 对象的映射；
- 建立 Python import smoke test；
- 建立至少一个真实 fixture 的 Python 读取测试；
- 记录 C ABI ownership 原则；
- 保持默认 C++ 构建不受 Python binding 影响。

### 3.2 范围外

- 不在第一版绑定 `Evaluator`；
- 不在第一版绑定 `SimulatorSession`、`SpectreSession`、`NgspiceSession`；
- 不在第一版绑定 `SessionFactory`；
- 不在第一版绑定 `OrderedConcurrentPool`；
- 不在第一版实现 C ABI；
- 不引入 numpy；
- 不做 wheel 发布；
- 不承诺 MATLAB、Rust、Julia 或其他语言接口；
- 不把业务 metric、objective、optimizer 放进 binding。

## 4. M4.1 推荐实现内容

M4.1 只做 pybind11 最小结果读取绑定。

候选绑定：

- `version()`
- `ResultStatus`
- `ScalarResult`
- `DcSweep`
- `AcResponse`
- `AcDerivedView`
- `TranWaveform`
- `read_dc_value()`
- `read_ac_response()`
- `read_tran_waveform()`
- `derive_ac_view()`
- `calculate_ugbw_and_phase_margin()`
- `calculate_settling_time()`

暂不绑定：

- `Evaluator`
- `SimulatorSession`
- `SpectreSession`
- `NgspiceSession`
- `SessionFactory`
- `OrderedConcurrentPool`
- C ABI。

这样做的理由：

- 生命周期简单；
- 工作量可控；
- 能先验证 Python 侧读取结果的体验；
- 不过早暴露执行层复杂对象；
- C++ core 后续变化时，binding 返工成本较低。

## 5. 目录规划

M4.1 使用：

```text
bindings/python/
  CMakeLists.txt
  spiceunion_py.cpp
  README.md
  tests/
    test_import.py
    test_read_results.py
```

目录语义：

- `bindings/` 表示外部语言绑定层；
- `bindings/python/` 表示 Python 是 C++ core 的可选调用入口；
- 不使用根目录 `python/`，避免让项目语义变成 Python 主项目。

## 6. Python API 形态

第一版采用 class / dataclass 风格返回值。

示例：

```python
import spiceunion

response = spiceunion.read_ac_response(result_dir, "vout", "ac.ac")

print(response.status)
print(response.message)
print(response.frequency_hz)
print(response.real)
print(response.imag)
```

约定：

- 字段名应尽量对应 C++ ResultIR；
- 读取失败不能伪装成 `None` 或 `0.0`；
- 失败状态必须保留 `status` 和 `message`；
- 不暴露 libpsf 类型；
- 不暴露 C++ STL 类型细节；
- 第一版不引入 numpy。

## 7. 测试策略

M4.1 先采用 CTest 调 Python。

建议覆盖：

- `python -c "import spiceunion"`；
- `version()`；
- 一个 scalar fixture；
- 一个 AC fixture；
- 一个 TRAN fixture；
- 一个失败读取 case。

不直接引入 pytest 的原因：

- SPICEUnion 当前仍是 C++ / CMake 主项目；
- M4.1 只需要最小 smoke test；
- CTest 可以统一 C++ 与 Python binding 测试入口；
- pytest 等 Python 测试生态可以在 Python API 变复杂后再引入。

## 8. CMake 开关

建议新增：

```cmake
SPICEUNION_BUILD_PYTHON_BINDINGS
SPICEUNION_BUILD_C_API
```

默认：

```cmake
SPICEUNION_BUILD_PYTHON_BINDINGS=OFF
SPICEUNION_BUILD_C_API=OFF
```

要求：

- 默认构建继续保持纯 C++；
- 不强制普通开发者安装 Python / pybind11；
- 打开 `SPICEUNION_BUILD_PYTHON_BINDINGS` 时才构建 Python extension；
- 打开 `SPICEUNION_BUILD_C_API` 时才考虑 C ABI 相关目标。

## 9. C ABI ownership 草案

C ABI 不进入 M4.1 第一版实现。

若后续进入 C ABI，必须先回答：

- 字符串由谁分配？
- 调用方如何释放字符串？
- double 数组由谁分配？
- result struct 是否固定布局？
- 是否使用 opaque handle？
- error message 生命周期如何管理？
- evaluator handle 如何 create / destroy？
- 是否允许跨线程调用同一个 handle？
- C ABI 是否暴露 ResultIR？
- C ABI 是否暴露 `Evaluator`？
- C ABI 是否暴露 Spectre / Ngspice backend？

当前原则：

- C ABI 使用 opaque handle 管理复杂对象；
- 所有由 SPICEUnion 分配的内存必须由 SPICEUnion 提供释放函数；
- C ABI 不直接暴露 C++ STL 类型；
- C ABI 不暴露第三方库类型；
- C ABI 第一版只做最小稳定子集；
- 没有 Python 之外的明确调用方前，不启动 C ABI 正式实现。

## 10. 分阶段计划

### M4.0 接入决策收口

状态：已完成。

产出：

- 本文档；
- M4.1 开发基线；
- 文档索引、开发计划书、开发路线图和 TODO 的状态同步。

### M4.1 pybind11 最小结果读取绑定

状态：待启动。

完成定义：

- 新增 `bindings/python/`；
- 可构建 Python extension；
- `python -c "import spiceunion"` 通过；
- `spiceunion.version()` 可调用；
- 至少一个已提交 fixture 可由 Python binding 读取；
- 失败读取 case 有明确 status / message；
- CTest 覆盖 Python import smoke test；
- 默认不开启 Python binding；
- README 与 `当前事实状态.md` 更新。

### M4.2 Python API 稳定化

状态：M4.1 后再启动。

目标：

- 固定 Python 返回对象字段；
- 补充最小 Python 使用示例；
- 明确异常、失败状态和错误消息规则；
- 评估是否需要 pytest。

### M4.3 执行层 binding 评估

状态：暂缓。

评估内容：

- 是否绑定 `Evaluator`；
- 是否提供更窄的 Python 运行函数；
- 是否需要 Spectre / Ngspice external 测试；
- 是否需要暴露批量任务状态。

### M4.4 C ABI 草案或实现

状态：暂缓。

进入条件：

- 明确存在 Python 之外的调用方；
- 或者项目需要稳定二进制 ABI；
- 或者用户明确要求 C ABI 优先。
