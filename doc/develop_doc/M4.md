# M4 pybind11 与 C ABI 接入开发文档

更新时间：2026-08-13

本文负责 SPICEUnion M4 阶段的开发规划与状态收口。

当前结论：

```text
M4.0 接入决策已收口；
M4.1 pybind11 最小结果读取绑定已完成；
M4.2 Python API 稳定化已完成；
C ABI 不进入第一版实现，仅保留 ownership 草案。
```

## 1. M4 目标

M4 的目标是让 SPICEUnion 的 C++ 能力以稳定、可测试、低负担的方式暴露给外部调用方。

当前第一调用方按 Python 处理。C ABI 只作为后续跨语言或稳定二进制接口需求出现时的扩展方向。

## 2. 已确认开发基线

| 事项 | M4 基线 |
|---|---|
| 第一实现路线 | 先 pybind11，后 C ABI |
| 第一版绑定范围 | 只绑定结果读取 helper 和少量基础结果类型 |
| Python 模块名 | `spiceunion` |
| binding 源码目录 | `bindings/python/` |
| Python 返回值形态 | class / dataclass 风格 |
| 数值数组 | 第一版使用普通 Python 容器，暂不引入 numpy |
| 测试入口 | 先用 CTest 调 Python |
| CMake 开关 | 默认关闭 Python binding 和 C ABI |
| `Evaluator` binding | 第一版不绑定，后续评估 |
| C ABI | 第一版不实现，只保留 ownership 草案 |

## 3. M4 范围

### 3.1 范围内

- 建立 pybind11 最小绑定；
- 暴露稳定的结果读取接口；
- 明确 C++ ResultIR 到 Python 对象的映射；
- 建立 Python import smoke test；
- 建立至少一个真实 fixture 的 Python 读取测试；
- 固定 Python result 对象字段、状态文本和 shape consistency helper；
- 记录 C ABI ownership 原则；
- 保持默认 C++ 构建不受 Python binding 影响。

### 3.2 范围外

- 不在第一版绑定 `Evaluator`；
- 不在第一版绑定 `SimulatorSession`、`SpectreSession`、`NgspiceSession`；
- 不在第一版绑定 `SessionFactory`；
- 不在第一版绑定 `OrderedConcurrentPool`；
- 不在第一版实现 C ABI；
- 不引入 numpy；
- 不做 wheel 发布；
- 不承诺 MATLAB、Rust、Julia 或其他语言接口；
- 不把业务 metric、objective、optimizer 放进 binding。

## 5. 目录规划

当前使用：

```text
bindings/python/
  CMakeLists.txt
  spiceunion_py.cpp
  README.md
  tests/
    test_api_contract.py
    test_import.py
    test_read_results.py
  examples/
    read_fixture_results.py
    analyze_fixture_results.py
```

目录语义：

- `bindings/` 表示外部语言绑定层；
- `bindings/python/` 表示 Python 是 C++ core 的可选调用入口；
- 不使用根目录 `python/`，避免让项目语义变成 Python 主项目。

## 6. Python API 形态

第一版采用 class / dataclass 风格返回值。

示例：

```python
import spiceunion

response = spiceunion.read_ac_response(result_dir, "vout", "ac.ac")

print(response.status)
print(response.message)
print(response.frequency_hz)
print(response.real)
print(response.imag)
```

约定：

- 字段名应尽量对应 C++ ResultIR；
- 读取失败不能伪装成 `None` 或 `0.0`；
- 失败状态必须保留 `status` 和 `message`；
- `status_text()` 返回 C++ `ResultStatus` 的稳定小写文本；
- 向量类结果提供 `shape_consistent()`；
- 不暴露 libpsf 类型；
- 不暴露 C++ STL 类型细节；
- 第一版不引入 numpy。

当前字段契约：

| Python 类型 | 字段 / 方法 |
|---|---|
| `ScalarResult` | `status`、`message`、`signal`、`value`、`ok()`、`status_text()` |
| `DcSweep` | `status`、`message`、`sweep_name`、`signal`、`sweep_values`、`values`、`ok()`、`status_text()`、`shape_consistent()`、`len()` |
| `AcResponse` | `status`、`message`、`signal`、`frequency_hz`、`real`、`imag`、`ok()`、`status_text()`、`shape_consistent()`、`len()` |
| `AcDerivedView` | `status`、`message`、`frequency_hz`、`magnitude_db`、`phase_deg`、`ok()`、`status_text()`、`shape_consistent()`、`len()` |
| `TranWaveform` | `status`、`message`、`signal`、`time_s`、`value`、`ok()`、`status_text()`、`shape_consistent()`、`len()` |
| `UgbwPhaseMarginResult` | `status`、`message`、`unity_gain_bandwidth_hz`、`phase_margin_deg`、`ok()`、`status_text()` |
| `SettlingTimeResult` | `status`、`message`、`settling_time_s`、`ok()`、`status_text()` |

异常规则：

- 普通读取失败返回 result 对象，不抛异常；
- 调用方应使用 `ok()` 判断成功；
- 失败原因使用 `status`、`status_text()` 与 `message`；
- Python 参数类型错误仍由 pybind11 抛出 Python 异常；
- 不用异常表达 `file_not_found`、`signal_not_found`、`unsupported_format` 这类预期失败。

## 7. 测试策略

M4.1 / M4.2 已采用 CTest 调 Python。

当前覆盖：

- `import spiceunion`；

- `libpsf_reader_enabled()`；
- scalar fixture；
- DC sweep fixture；
- AC fixture；
- TRAN fixture；
- 失败读取 case。
- result 对象字段和基础方法契约；
- 示例脚本 smoke test。

不直接引入 pytest 的原因：

- SPICEUnion 当前仍是 C++ / CMake 主项目；
- M4.1 / M4.2 只需要最小 smoke test 与 API contract test；
- CTest 可以统一 C++ 与 Python binding 测试入口；
- pytest 等 Python 测试生态可以在 Python API 变复杂后再引入。

## 8. CMake 开关

已新增：

```cmake
SPICEUNION_BUILD_PYTHON_BINDINGS
SPICEUNION_BUILD_C_API
```

默认：

```cmake
SPICEUNION_BUILD_PYTHON_BINDINGS=OFF
SPICEUNION_BUILD_C_API=OFF
```

事实：

- 默认构建继续保持纯 C++；
- 不强制普通开发者安装 Python / pybind11；
- 打开 `SPICEUNION_BUILD_PYTHON_BINDINGS` 时才构建 Python extension；
- `SPICEUNION_BUILD_C_API=ON` 当前直接报错，提示该阶段尚未实现。

libpsf 与 Python extension 同时启用时，静态 libpsf 需要能被链接进 shared module。
本机已补充 PIC 构建路径：

```text
local/external/libpsf/install-pic
```

CMake 当前优先查找 `install-pic`，再回退到 `install`。

## 9. C ABI ownership 草案

C ABI 不进入 M4.1 第一版实现。

若后续进入 C ABI，必须先回答：

- 字符串由谁分配？
- 调用方如何释放字符串？
- double 数组由谁分配？
- result struct 是否固定布局？
- 是否使用 opaque handle？
- error message 生命周期如何管理？
- evaluator handle 如何 create / destroy？
- 是否允许跨线程调用同一个 handle？
- C ABI 是否暴露 ResultIR？
- C ABI 是否暴露 `Evaluator`？
- C ABI 是否暴露 Spectre / Ngspice backend？

当前原则：

- C ABI 使用 opaque handle 管理复杂对象；
- 所有由 SPICEUnion 分配的内存必须由 SPICEUnion 提供释放函数；
- C ABI 不直接暴露 C++ STL 类型；
- C ABI 不暴露第三方库类型；
- C ABI 第一版只做最小稳定子集；
- 没有 Python 之外的明确调用方前，不启动 C ABI 正式实现。
