# M3 多仿真器接入与结果语义收敛文档

更新时间：2026-08-13

本文负责 SPICEUnion M3 阶段的现状总结、最终推进边界和最小收口计划。

当前结论：

```text
M3.0-M3.4 已完成基础闭环；
M3.5 OrderedConcurrentPool 独立化已完成；
M3 后续只做 Spectre 侧 DC sweep 最小收口；
MOS I-V / gm/Id、netlist template、Ngspice .op、legacy sensitivity、PSFXL transient 继续暂缓。
```

## 1. M3 目标

M3 的目标是验证 SPICEUnion 是否能从单一 Spectre backend 扩展到至少两个真实仿真器 backend，并保持统一的执行语义与结果读取语义。

M3 关注：

- 第二仿真器 Ngspice 接入；
- batch 执行语义；
- AC / TRAN / DC sweep 基础结果语义；
- Spectre 与 Ngspice 的同类场景对照；
- `Evaluator`、`TaskResult`、`ResultIR` 是否足够支撑多 backend。

M3 不关注：

- 完整 netlist IR；
- 通用 netlist 生成 DSL；
- MOS gm/Id lookup table；
- optimizer；
- Hspice / Xyce；
- Python binding；
- C ABI。

## 2. 当前已完成事实

### 2.1 Spectre backend

已具备：

- `spectre +interactive` 启动；
- SKILL handshake；
- circuit handle 初始化；
- 参数写入；
- `(sclRun "all")`；
- completion 判断；
- graceful / force stop；
- evaluator multi-worker batch；
- PSF `dcOp.dc` scalar fixture；
- PSF `ac.ac` / `stb.stb` swept complex fixture；
- 普通 PSF transient fixture；
- Spectre RC low-pass AC fixture；
- Spectre RC charging TRAN fixture。

当前边界：

- Spectre 23.1 PSFXL transient fixture 当前明确返回 `kUnsupportedFormat`；
- legacy sensitivity 读取未实现；
- Spectre 侧 DC sweep 尚未与 Ngspice `DcSweep` 做同类语义对照。

### 2.2 Ngspice backend

已具备：

- `ngspice -b` batch mode；
- 每个 worker 独立工作目录；
- 内置任务 netlist 渲染；
- ngspice stdout / 输出文件读取；
- failure 通过 `TaskResult` 返回；
- `make_ngspice_session_factory(task)`；
- `make_ngspice_evaluator(options, task)`。

当前 `NgspiceBuiltinTask`：

| 任务 | 输出文件 | 输出格式 | ResultIR |
|---|---|---|---|
| `kRcAc` | `rc_ac.out` | 三列 `frequency real imag` | `AcResponse` |
| `kRcTran` | `rc_tran.out` | 两列 `time value` | `TranWaveform` |
| `kResistorDividerDc` | `resistor_divider_dc.out` | 两列 `sweep_value value` | `DcSweep` |

当前边界：

- 不是任意 Ngspice netlist 执行器；
- 只支持内置教学级 batch 任务；
- 尚未实现 `.op` operating point；
- 尚未进入 MOS I-V / gm/Id。

### 2.3 ResultIR 与结果读取

M3 相关已用到：

| ResultIR | 当前状态 |
|---|---|
| `ScalarResult` | Spectre DC operating point scalar 已覆盖 |
| `DcSweep` | Ngspice resistor divider DC sweep 已覆盖 |
| `AcResponse` | Spectre / Ngspice RC AC 已覆盖 |
| `AcDerivedView` | AC magnitude / phase 派生已覆盖 |
| `TranWaveform` | Spectre / Ngspice RC TRAN 已覆盖 |
| `ReadResult<T>` | 显式 status / message 失败语义已覆盖 |

当前 `DcSweep` 只表达：

```text
单 sweep axis、单 signal 实数响应
```

它尚未表达：

- 多条曲线；
- family curve；
- 多维 sweep；
- MOS I-V 曲线族；
- gm/Id lookup table。

M3 最小收口不扩展 `DcSweep`。

### 2.4 Spectre / Ngspice 对照

已完成的同类语义对照：

| 场景 | Spectre | Ngspice | 状态 |
|---|---|---|---|
| RC low-pass AC | 已有 fixture | 已有 external test | 已完成基础对照 |
| RC charging TRAN | 已有 fixture | 已有 external test | 已完成基础对照 |
| resistor divider DC sweep | 未做 Spectre fixture | 已有 external test | M3 最小收口目标 |

当前判断：

```text
AC / TRAN 已足够证明第二仿真器基础闭环；
DC sweep 只有 Ngspice 侧，尚不足以证明跨 backend DC sweep 语义一致；
M3 最小收口只补 Spectre 侧 resistor divider DC sweep 对照。
```

## 6. 暂缓项说明

### 6.1 MOS I-V / gm/Id

暂缓原因：

- 当前没有明确 MOS 模型、工艺节点和真实消费者；
- 可能需要 family curve 或多维 sweep；
- gm/Id lookup table 更像上层应用或独立模块，不应提前写进 SPICEUnion core。

### 6.2 netlist template / DSL

暂缓原因：

- 当前 M3 最小收口不需要完整 netlist IR；
- 现有 `ParameterState` 与内置任务枚举足够支撑当前测试；
- 不为了未来可能性提前扩大项目复杂度。

### 6.3 Ngspice `.op`

暂缓原因：

- 当前已有 Ngspice AC / TRAN / DC sweep；
- `.op` 不是 M3 最小收口必须项；
- 优先级低于 Spectre / Ngspice DC sweep 对照。

### 6.4 legacy sensitivity 与 PSFXL transient

暂缓原因：

- legacy sensitivity 缺可信参考值与 fixture；
- PSFXL transient 已有 unsupported 边界；
- 两者都不是 M3 最小收口的必要条件。
