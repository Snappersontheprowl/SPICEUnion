# M3.3 Spectre 与 Ngspice 同类 TRAN 语义对照

时间：2026-08-06

本文记录 M3.3 的事实状态：在 M3.2 已经证明 Spectre PSF 与 Ngspice `wrdata` 能复用
同一套 `AcResponse` 语义检查之后，继续补齐 Spectre 侧 RC charging TRAN fixture，并验证
`TranWaveform` 也能跨 backend 复用。

## 当前结论

M3.3 已完成 Spectre / Ngspice 同类 TRAN 语义对照。

新增材料：

| 类型 | 路径 | 作用 |
|---|---|---|
| Spectre 源 netlist | `tests/fixtures/spectre/rc_charging_tran/input.scs` | 记录可复现输入 |
| Spectre 固化 PSF | `tests/fixtures/psf/spectre_rc_charging_tran.raw/tran.tran.tran` | libpsf reader 与 ResultIR 语义测试 |
| 公共测试 helper | `tests/support/rc_semantics.hpp` | RC charging TRAN 物理语义检查 |
| 语义契约测试 | `tests/simulation_semantics_test.cpp` | Spectre PSF -> `TranWaveform` -> RC charging semantic check |

本次 Spectre 23.1 生成的是单个普通 transient PSF 文件：

```text
tran.tran.tran
```

没有生成 `.psfxl` / `.sig` 伴随文件。因此该 fixture 可由当前 `henjo/libpsf` backend 读取。

## Spectre RC charging TRAN fixture

源 netlist：

```text
tests/fixtures/spectre/rc_charging_tran/input.scs
```

电路：

```text
Vin -- R1 -- out
             |
             C1
             |
             0
```

参数：

| 参数 | 值 |
|---|---:|
| `R` | `1 kΩ` |
| `C` | `1 pF` |
| `Vin` | `1 V` |
| `tran stop` | `10 ns` |
| `maxstep` | `10 ps` |
| 初始 `out` | `0 V` |

理论响应：

```text
v(out, t) = Vin * (1 - exp(-t / (R*C)))
τ = RC = 1 ns
```

关键 Spectre 设置：

```spectre
C1 (out 0) capacitor c=c ic=0
tran tran stop=stop maxstep=maxstep skipdc=yes
save out
```

这里使用 `ic=0` 与 `skipdc=yes`，目的是避免 operating point 直接把电容置为稳态电压，
从而得到从 0V 向 1V 充电的曲线。

生成命令要点：

```bash
spectre tests/fixtures/spectre/rc_charging_tran/input.scs \
  -64 \
  -raw spectre_rc_charging_tran.raw \
  -format psfbin
```

本机 Spectre 版本：

```text
Spectre 23.1.0.063 64bit
```

生成后的固化结果：

```text
tests/fixtures/psf/spectre_rc_charging_tran.raw/tran.tran.tran
```

该结果可由当前 `SPICEUNION_ENABLE_LIBPSF_READER=ON` 下的 `read_tran_waveform()` 读取，
signal 名称为：

```text
out
```

读取时需要显式指定文件名：

```cpp
read_tran_waveform(fixture.string(), "out", "tran.tran.tran");
```

## 当前测试覆盖

Ngspice external TRAN 测试：

```text
NgspiceSessionExternalTest.RunsRcChargingTranWhenExternalNgspiceIsEnabled
```

路径：

```text
Ngspice wrdata rc_tran.out
  -> read_ngspice_wrdata_tran_waveform()
  -> TranWaveform
  -> expect_rc_charging_tran_semantics()
```

Spectre PSF fixture 语义测试：

```text
RcTranSemanticContractTest.SpectreRcChargingTranFixtureUsesCommonTranWaveformSemantics
```

路径：

```text
Spectre PSF tran.tran.tran
  -> read_tran_waveform()
  -> TranWaveform
  -> expect_rc_charging_tran_semantics()
```

两个 backend 的原始输出格式不同：

| Backend | 原始输出 | Reader |
|---|---|---|
| Ngspice | `wrdata` 文本两列 | `read_ngspice_wrdata_tran_waveform()` |
| Spectre | PSF `tran.tran.tran` | `read_tran_waveform(..., "tran.tran.tran")` |

但进入 `TranWaveform` 后，二者复用同一套 RC charging 语义检查。

## 与 PSFXL 边界的关系

M2.3 中保留的 `spectre_materials_psfxl_tran.raw/` 仍然是明确边界样本，当前 libpsf backend 仍不支持
PSFXL transient。

M3.3 的新 fixture 说明：

```text
并不是所有 Spectre 23.1 transient 都必然落入 PSFXL 边界；
对于当前简单 RC transient，Spectre 23.1 可以生成当前 libpsf backend 可读取的普通 PSF 文件。
```

因此：

- `spectre_rc_charging_tran.raw/` 用于验证普通 transient `TranWaveform` 语义；
- `spectre_materials_psfxl_tran.raw/` 继续用于验证 PSFXL unsupported 边界。
